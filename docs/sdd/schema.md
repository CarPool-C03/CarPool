# Schema PostgreSQL

Fonte delle scelte implementative dello schema L1. I nomi di tabelle e colonne
restano quelli di [CD_persistenza.puml](./CD_persistenza.puml).

## Convenzioni

- PK `id`: `INTEGER GENERATED BY DEFAULT AS IDENTITY`.
- Date e ore: `TIMESTAMPTZ`; importi: `NUMERIC(8,2)`; punteggi: `SMALLINT`;
  testo libero: `TEXT`.
- I campi obbligatori sono `NOT NULL`; gli attributi opzionali del diagramma
  accettano `NULL`.
- Le FK usano `ON DELETE RESTRICT`: il modello mantiene i riferimenti; la
  cancellazione dell'account segue l'anonimizzazione prevista dal SDD.
- Gli ID esposti dalle API sono interi.

## Tipi e limiti

Ogni tabella ha `id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`.
Le altre colonne sono:

| Tabella | Colonne e tipi |
|---|---|
| Organizzazione | `denominazione VARCHAR(200) NOT NULL`; `attiva BOOLEAN NOT NULL DEFAULT TRUE` |
| DominioEmail | `dominio VARCHAR(254) NOT NULL UNIQUE`; `organizzazioneId INTEGER NOT NULL` |
| Sede | `nome VARCHAR(100) NOT NULL`; `indirizzo VARCHAR(255) NOT NULL`; `organizzazioneId INTEGER NOT NULL` |
| Evento | `nome VARCHAR(150) NOT NULL`; `dataOraInizio TIMESTAMPTZ NOT NULL`; `luogo VARCHAR(255) NOT NULL`; `organizzazioneId INTEGER NOT NULL` |
| Account | `email VARCHAR(254) NOT NULL UNIQUE`; `passwordHash VARCHAR(255) NOT NULL` (bcrypt); `tipoAccount VARCHAR(30) NOT NULL`; `stato VARCHAR(30) NOT NULL` |
| Sessione | `hashToken VARCHAR(255) NOT NULL UNIQUE`; `ultimaAttivita TIMESTAMPTZ NOT NULL`; `accountId INTEGER NOT NULL` |
| TokenVerifica | `tipo VARCHAR(30) NOT NULL`; `hashToken VARCHAR(255) NOT NULL UNIQUE`; `scadenza TIMESTAMPTZ NOT NULL`; `usatoIl TIMESTAMPTZ NULL`; `accountId INTEGER NOT NULL` |
| Membro | `nome VARCHAR(100) NOT NULL`; `cognome VARCHAR(100) NOT NULL`; `ruoloMobilityManager BOOLEAN NOT NULL DEFAULT FALSE`; `accountId INTEGER NOT NULL UNIQUE`; `organizzazioneId INTEGER NOT NULL` |
| Veicolo | `modello VARCHAR(100) NOT NULL`; `colore VARCHAR(50) NOT NULL`; `numeroPostiPasseggeri INTEGER NOT NULL`; `membroId INTEGER NOT NULL UNIQUE` |
| Viaggio | `dataOraPartenza TIMESTAMPTZ NOT NULL`; `puntoPartenza VARCHAR(255) NOT NULL`; `destinazioneRitorno VARCHAR(255) NULL`; `postiOfferti INTEGER NOT NULL`; `contributoIndicativoEuro NUMERIC(8,2) NULL`; `stato VARCHAR(20) NOT NULL`; `direzioneEvento VARCHAR(20) NULL`; `conducenteId INTEGER NOT NULL`; `sedeId INTEGER NULL`; `eventoId INTEGER NULL` |
| RichiestaPrenotazione | `stato VARCHAR(20) NOT NULL`; `passeggeroId INTEGER NOT NULL`; `viaggioId INTEGER NOT NULL` |
| Valutazione | `punteggio SMALLINT NOT NULL`; `commento TEXT NULL`; `autoreId INTEGER NOT NULL`; `valutatoId INTEGER NOT NULL`; `viaggioId INTEGER NOT NULL` |
| Messaggio | `testo TEXT NOT NULL`; `dataOraInvio TIMESTAMPTZ NOT NULL`; `mittenteId INTEGER NOT NULL`; `viaggioId INTEGER NOT NULL` |

Tutti i campi `...Id` elencati sono FK verso la PK `id` della tabella
corrispondente nel diagramma. I timestamp degli eventi applicativi vengono
forniti dal chiamante.

## Valori e vincoli

- `Account.tipoAccount`: `Membro`, `Amministratore`.
- `Account.stato`: `InAttesaDiVerifica`, `Attivo`, `Eliminato`; default
  `InAttesaDiVerifica`.
- `Account.email` è memorizzata in minuscolo (vincolo `account_email_minuscola`); il confronto in login e registrazione avviene sull'indirizzo normalizzato.
- `Viaggio.stato`: `Attivo`, `Cancellato`, `Concluso`; default `Attivo`.
- `RichiestaPrenotazione.stato`: `InAttesa`, `Accettata`, `Rifiutata`,
  `Annullata`, `Completata`; default `InAttesa`.
- `TokenVerifica.tipo`: `VerificaEmail`, `RecuperoCredenziali`.
- `Viaggio.direzioneEvento`: `Andata`, `Ritorno`; se il viaggio ha una sede,
  `direzioneEvento` e `destinazioneRitorno` devono essere `NULL`.
- `Viaggio` deve riferirsi esattamente a una tra `sedeId` ed `eventoId`.
- `postiOfferti` e `numeroPostiPasseggeri` devono essere almeno 1;
  `punteggio` deve essere compreso tra 1 e 5.
- `Account.email` e `DominioEmail.dominio` sono univoci; `Membro.accountId` e
  `Veicolo.membroId` sono univoci.
- `Valutazione` è univoca per `(autoreId, valutatoId, viaggioId)`.
- Una sola richiesta per coppia `(passeggeroId, viaggioId)` può essere
  `InAttesa` o `Accettata`; gli altri stati non sono coperti dall'indice
  univoco parziale.

## Indici

- Ricerca viaggi: `(stato, dataOraPartenza, sedeId)` (`viaggio_ricerca_idx`).
- Richieste attive: indice univoco parziale su `(passeggeroId, viaggioId)`
  per gli stati `InAttesa` e `Accettata`
  (`richiesta_prenotazione_attiva_unica`).
- Chiusura delle sessioni e ricerca dei token di un account: indici su `Sessione.accountId` (`sessione_account_idx`) e `TokenVerifica.accountId` (`token_verifica_account_idx`).

## Token e password

`Sessione` conserva solo `hashToken` del token casuale e `ultimaAttivita`.
`TokenVerifica` conserva `hashToken`, `scadenza` e `usatoIl` nullable; la
presenza di `usatoIl` indica che il token è stato utilizzato. Le password
degli account sono salvate solo come hash bcrypt.
